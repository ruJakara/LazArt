# LazArt Robot Workshop · v0.2

Локальная экономическая игра «Маленькая мастерская». Настрой шесть ИИ-работников, выпусти не меньше 20 исправных роботов-пылесосов за семь дней и сохрани положительный баланс.

## Запуск ученика

**Дважды нажми `run_game.bat`.** Игра сама откроется в браузере.

Нужны Windows 10/11, Python 3.10+ и современный браузер. Если Python уже установлен, больше ничего устанавливать не нужно. Нет пакетов, npm, CDN, API, облака, регистрации или внешних шрифтов. После установки Python интернет не нужен.

Окно запуска оставь открытым. Чтобы выключить игру, закрой это окно или нажми Ctrl+C. При следующем запуске нажми «Загрузить», если раньше сохранял игру.

Сервер слушает только `127.0.0.1` и выбирает свободный порт. Можно одновременно запустить несколько экземпляров. Сохранение у папки игры одно: `saves/current.json`.

Прямое открытие `web/index.html` покажет подсказку запустить BAT: HTML — интерфейс, Python — источник истины для денег, склада и производства. Это согласованный вариант запуска прототипа с двумя режимами.

## Как играть

1. Запусти первый день с исходными настройками и наблюдай за картой. Мастерская намеренно неэффективна, но первый день не закрывает её.
2. Роботы переносят детали и пылесосы, выполняют операции, сообщают о проблемах. Пауза останавливает смену; ×2 и ×4 ускоряют её. Обычная смена занимает примерно минуту.
3. Нажми на робота, участок или имя работника внизу. В небольшой карточке видны задача и расходы, кнопка «Настроить» открывает конфигуратор. Во время смены настройки доступны только для просмотра.
4. В конце дня появится короткий отчёт: продажи, прибыль, брак и два наблюдения. Подробные финансы раскрываются отдельно. Журнал и склад открываются кнопками под картой.
5. Повтори прогон с тем же seed и сравни результаты. Настройки сохраняются, деньги и склад сбрасываются. «Новый seed» меняет случайность, «Сбросить урок» возвращает исходную конфигурацию.

Сохранение, загрузка, переключение AUTO/PYTHON и перезапуск находятся в меню сверху. «Сохранить» записывает весь прогон и базу сравнения в JSON. «Загрузить» восстанавливает его. Сохранять и менять конфигурацию можно между завершёнными днями. Отчёт любого сыгранного дня можно выбрать в окне отчётов. Журнал показывает текущую смену или последний завершённый день; все события сохраняются в JSON.

День выполняется Python-движком по операциям, а карта получает результат каждого шага. Закупки, расход деталей и выручка изменяются в ходе смены. Итоги не рассчитываются заранее. Пауза блокируется и в движке. Повтор запроса с тем же номером шага не выполняет операцию второй раз.

Если обновить вкладку, она подключится к текущей смене на сервере. Пауза и экономическое состояние сохранятся; текущая анимация начнётся заново без повторного списания денег. Если закрыть сам сервер, незавершённая смена не сохраняется. Перезапуск во время смены отменяет её; завершённые дни доступны для сравнения.

В игре возможны выигрыш, банкротство, остановка линии и поражение из-за возвратов. Успех определяется производством и экономикой, обычных очков нет. Стратегии с упором на экономию, качество и выпуск проверяются автотестами на разных seed.

## PYTHON

Переключись в PYTHON → «Открыть папку» → открой `student/solution.py` в любом текстовом редакторе. Сохрани файл, нажми «Проверить код», посмотри распознанную конфигурацию, затем «Применить». Проверка сама настройки не меняет. После применения запускай день обычной кнопкой.

```python
def configure_factory(factory):
    warehouse = factory.worker("warehouse")
    warehouse.set_model("standard")
    warehouse.set_context(5)
    warehouse.set_instructions("Перед закупкой проверяй остатки.")
    warehouse.add_tool("check_stock")
    warehouse.enable_rule("check_before_order")
```

Также доступны `disable_rule`, `remove_tool`. Работники: `reception`, `warehouse`, `engineer`, `assembler`, `qc`, `cleaner`. Допустимый Context: **0, 2, 5, 10, 20**; пример с 4 в исходном ТЗ заменён на 5 для согласованности. Имена инструментов и Rules видны в карточках AUTO и JSON-контенте. В PYTHON карточки доступны только для просмотра.

Текст Instructions не интерпретируется как естественный язык: поведение задают Rules. Python запускается отдельным процессом с лимитом 3 секунды. Синтаксическая ошибка, неизвестный Tool и бесконечный цикл не останавливают игру. Это ограниченный учебный API, **не security sandbox**. Исполняй только свой код.

## Что считается

- Каждая попытка действия оплачивает модель, контекст и обслуживание доступных Tools. Вызванный Tool дополнительно имеет свою цену. При отсутствующем Tool его цена не начисляется, но попытка мышления стоит денег.
- Модель, Rules, доступные инструменты, последние события и загрязнение цеха влияют на результат. Контекст сохраняет реальные события данного работника; размер 20 добавляет цену и небольшой штраф эффективности.
- Склад закупает и принимает детали, рецепт реально списывается при сборке. Оплаченная непринятая поставка остаётся в состоянии. Переделка требует дополнительного датчика.
- Дефекты — все неудачные сборки, в том числе исправленные. Возвраты — неисправные изделия, пропущенные к клиенту. Возврат не даёт выручку и вызывает штраф. Именно доля возвратов определяет критическое качество.
- Отчёт отражает денежный поток: выручка минус закупки, ИИ, эксплуатация и штрафы. Стартовые шесть комплектов получены вместе с мастерской. Стоимость оставшегося склада показана отдельно в итоговом отчёте.
- При сравнении учитываются первые N дней, где N — меньшее число сыгранных дней двух прогонов. Если seed отличается, сравнение блокируется. Можно менять конфигурацию между днями.

## Структура и еженедельные изменения

| Путь | Назначение |
|---|---|
| `run_game.bat`, `server.py` | Запуск, локальный HTTP, разрешённые команды |
| `engine/game.py` | Состояние, прогон, сохранение, сравнение |
| `engine/simulation.py` | Производственная цепочка и события |
| `engine/economy.py`, `scoring.py` | Цены, отчёты, победа, выводы |
| `engine/workers.py`, `validator.py`, `student_runner.py` | Единый формат AUTO/PYTHON и API ученика |
| `content/*.json` | Модели, роли, рецепты, инструменты, карточки инструкций, баланс |
| `lessons/lesson_01.json` | Цели и доступный контент первого урока |
| `web/app.js`, `web/map.js` | Команды и часы смены; отдельный Canvas-рендер карты, перемещений и грузов |
| `web/index.html`, `styles.css` | Минимальный основной экран; настройки и отчёты по запросу |
| `student/` | Код ученика и шаблон |
| `tests/` | Проверки ядра, HTTP и браузерного рабочего пути |

Сначала меняй баланс и контент JSON. Новую механику добавляй отдельным модулем engine и подключай явно к симуляции. `Game` принимает переданный `content`, поэтому следующий урок можно собирать отдельной конфигурацией и модулями, не меняя JSON Lesson 01. Сам загрузчик и UI пока рассчитаны на один урок, один продукт и шесть участков; новые роли и карта требуют соответствующего расширения. Skills, RAG, Planner и остальные будущие серии сейчас не реализованы.

Формат события: `{day, tick, actor, event, level, message, data}`. События действий содержат Tool и фактический AI cost. Они служат журналом и памятью, сохраняются с прогоном и подходят для будущего Replay. Одинаковый seed и одинаковая последовательность конфигураций/команд дают одинаковые результаты. `DaySimulation.steps()` приостанавливается после реальных операций. `Game.run_day()` выполняет те же шаги без ожидания интерфейса, поэтому тесты и оба режима используют одно ядро.

## Проверки разработчика

Из папки игры:

```text
python -m unittest discover -s tests -v
python server.py --no-browser --port 8765 --seed 42
```

Для UI-проверки, только на компьютере разработчика с установленным Playwright:

```text
node tests/browser_smoke.cjs
```

Если Playwright установлен вне проекта, настрой `NODE_PATH` на его `node_modules`. `WORKSHOP_URL` задаёт URL тестового сервера, `WORKSHOP_PYTHON` — Python для сравнения с прогоном без браузера. Проверка временно меняет `solution.py` и сохранение и восстанавливает их в `finally`. Выполняй её на отдельном тестовом сервере, не в ученическом прогоне. Проверяются движение грузов, пауза/обновление страницы, скорости, 7 дней, AUTO/PYTHON, сохранения и сравнение. Отдельная смена проходит на настоящем времени ×4 без виртуальных часов. Скриншоты и результат находятся в `output/live-browser/` и не входят в Git. Для запуска ученика эти инструменты не нужны.
